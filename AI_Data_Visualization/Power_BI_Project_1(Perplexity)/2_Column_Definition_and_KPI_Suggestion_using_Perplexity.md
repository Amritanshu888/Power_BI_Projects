# Power BI Project — Understanding the Dataset & Planning the Report

## 1. Objective of the Session

The purpose of this session is to **understand the dataset before starting Power BI report creation**.

The instructor wants to use **Perplexity as an AI assistant** to help with three major tasks:

1. Understand the meaning/definition of each column.
2. Plan a **two-page Power BI report**.
3. Get suggestions for:

   * Key Performance Indicators (**KPIs**)
   * Suitable charts/visuals
   * **DAX functions/measures** wherever required

The important idea is:

> Before creating a dashboard, first understand what each field means and then use AI to help plan meaningful KPIs and visualizations.

# 3. Get All Column Names Using INFORMATION_SCHEMA

The instructor asks Perplexity for SQL code that will retrieve all column names from the `dbo.diamonds` table.

The suggested SQL query is:

```sql
SELECT column_name
FROM information_schema.columns
WHERE table_name = 'diamonds'
  AND table_schema = 'dbo';
```

### Understanding the query

### `information_schema.columns`

This is a SQL Server metadata view containing information about columns in databases.

It can provide information such as:

* Column name
* Data type
* Maximum length
* Whether NULL is allowed
* etc.

Here, the instructor only needs the column names.

### `WHERE table_name = 'diamonds'`

This restricts the result to the table:

```text
diamonds
```

### `AND table_schema = 'dbo'`

This further specifies that the table belongs to the:

```text
dbo
```

schema.

Therefore, the query retrieves the columns specifically from:

```text
dbo.diamonds
```

# 7. Important: Treat AI Definitions as "Possible Definitions"

The instructor makes an important point here.

The definitions generated by Perplexity should **not automatically be considered 100% correct**.

The prompt asks for:

> **Possible definitions**

This means the AI is being used as a starting point for understanding the data.

You should:

1. Review the definitions.
2. Understand what each field represents.
3. Validate important definitions against reliable dataset documentation if necessary.
4. Decide which definitions make sense for the report.

### Key principle

> AI suggestions are recommendations, not necessarily final decisions.

The instructor explicitly says that it isn't necessary to accept everything generated by Perplexity.

# 21. SQL Query to Remember

The most important SQL concept introduced in this lecture is querying metadata to retrieve column names:

```sql
SELECT column_name
FROM information_schema.columns
WHERE table_name = 'diamonds'
  AND table_schema = 'dbo';
```

### General template

You can reuse this for other tables by changing the table name:

```sql
SELECT column_name
FROM information_schema.columns
WHERE table_name = 'YOUR_TABLE_NAME'
  AND table_schema = 'dbo';
```

This is useful whenever you need to quickly discover the columns available in a SQL Server table.

# 23. Key Lessons from the Session

### Lesson 1 — Understand data before visualization

Don't immediately start creating charts.

First understand:

* What each column means.
* What type of data it contains.
* What the units are.
* Which fields are categorical.
* Which fields are numerical.

You don't have to manually inspect every table.

Metadata queries such as:

```sql
INFORMATION_SCHEMA.COLUMNS
```

can quickly tell you what columns exist.

> Possible definitions of these columns.

---

### Lesson 4 — AI can help with dashboard planning

Instead of randomly choosing charts, you can ask AI to suggest:

* KPIs
* Charts
* Page themes
* DAX calculations
* Analytical questions

---

Don't blindly copy AI-generated DAX or visualization recommendations.
